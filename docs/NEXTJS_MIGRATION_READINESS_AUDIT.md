## 9. Migration Risks

### High Risk

1. **Removing TanStack Router while keeping 74 route files** — TanStack uses file-based routing with different conventions than Next.js. Every route file must be moved and adapted.
2. **`@lovable.dev/vite-tanstack-config` is the core build config** — It wraps TanStackStart + ViteReact + Tailwind + tsconfig-paths + Nitro + Lovable plugins. Removing this means rewriting the entire build pipeline.
3. **SSR differences** — TanStack Start uses Nitro for SSR; Next.js uses its own server. The `src/server.ts` file must be replaced with Next.js API routes / server components.
4. **Auth must be reimplemented** — Current "auth" is a mock auto-login. Next.js migration requires real auth (NextAuth.js, Supabase Auth, or custom solution).
5. **`DATA_MODE` lock must be released** — After migration, `DATA_MODE` must switch to `"backend"` and writes must be enabled. This is the most sensitive change.

### Medium Risk

6. **Route parameter syntax differs** — TanStack uses `$id.tsx`, Next.js uses `[id]/page.tsx`. All ~20 parameterized routes need changes.
7. **`__root.tsx` structure** — The root layout with `QueryClientProvider`, `I18nProvider`, `AuthProvider`, `Toaster` must be ported to `app/layout.tsx`.
8. **Tailwind v4 with Next.js** — Tailwind v4 is new; needs proper integration with Next.js.
9. **React Query vs Server Actions** — Decide whether to keep `react-query` or replace with Next.js Server Actions for data fetching.

### Low Risk

10. **Directory restructuring** — Moving `src/components/`, `src/lib/` — pure organizational work.
11. **shadcn/ui components** — All framework-agnostic; no changes needed.
12. **Demo data** — Can be preserved as-is in the new structure.
